## 1. 終了経路が3つある

話の終わりは1種類ではない。**1つでも見落とすと、完走している話を「停止」と誤判定する。**

| 記法 | 実際の処理 | 使っている話 |
|---|---|---|
| `{ed:true}` | `#ed` に `.show` | 第一話〜第十一話の多く |
| `{fin:true}` | `#curtain` に「◆ おわり ◆」を出す | m1 / m2 / m3 / x1 / en1 |
| `{ed:true}` かつ `state.ep==="8"` | **PVに分岐**して `#pv` に `.show` | 最終話のみ |

`{fin:true}` は `#ed` を一切触らない。`startEd()` は `state.ep==="8"` のとき
`startPv()` に抜けるので、最終話も `#ed` を見ていると captured できない。

自動テストを書くときは3つ全部見る。`tools/qa.py` はそうなっている。

## 2. 選択肢は押しても DOM に残る

`showChoice` のクリックハンドラは `box.classList.remove("show")` で
`display:none` にするだけ。**ボタンは次の `showChoice` が呼ばれるまで DOM に残る。**

`#choiceBox .choice` の有無だけで「選択肢が出ている」と判定すると、
見えないボタンを押し続けて無限ループする。実際にこれで第一話の i=48 を
**881回クリック**し、レンダラが 84% CPU で回り続けた。

```js
// 正しい判定
if (box.classList.contains('show')) {
  const cb = box.querySelectorAll('.choice');
  ...
}
```

人間には `display:none` で押せないので、**実機では起きない**。
自動化したときだけ出る問題。

`showChoice` は `state.skip=false` も毎回セットする。
スキップで走らせているなら選択後に戻すこと。

## 3. `<script>` は3ブロックある

```python
re.search(r'<script>(.*)</script>', s, re.S)   # ← 壊れる
```

`.*` が欲張りなので**最後の `</script>` まで飲み込み**、途中の `</script>` が
JSとして解釈されて必ず `SyntaxError: Unexpected token '<'` になる。
**正しいビルドを「壊れている」と誤判定する。**

1ブロックずつ非貪欲で取り出して、それぞれ `node --check` する。

```python
re.findall(r'<script>(.*?)</script>', s, re.S)  # ← 正しい
```

## 4. ASSETS の行末カンマ

`ASSETS` の中にはSDスプライトが**3つで1行・行末カンマ無し**の箇所がある。

```
  sdAmai:"data:…", sdDere:"data:…", sdWarai:"data:…",    // ED
```

(この行末カンマは v62 で構文エラーを出した後に足したもの)

気づかず直後に追記すると構文エラーになる。しかも `node --check` の
エラー出力に base64 が数MB混ざって、何が起きたかわからなくなる。

**挿入前に assert でカンマを確認する。** 行を読むときは base64 をマスクする。

## 5. 更新したのに古い版が出る

この作品は**2回、別の原因で**これを踏んでいる。症状が同じなので混同しないこと。

1. **ファイル名ベースのURLで配っていた** — ファイル名が変わるとURLが変わる。
   → `crc/index.html` 固定にした
2. **GitHub の raw 配信はブランチ名に対してCDNキャッシュを持つ** —
   マージ直後に `main` のURLを開いても数分〜数十分は古い版が返る
   → **コミットSHA直指定のURLで配る**

どちらの場合も「ファイルは正しい」「マージは済んでいる」で終わらせず、
**実データを確認する**。git の blob ハッシュ比較が一番確実:

```bash
git rev-parse HEAD:crc/index.html
git rev-parse origin/main:crc/index.html
```

## 6. `playBgm` は既定でループする

```js
async function playBgm(key, loop=true)   // ← 既定で true
```

**曲が尺切れするとループ頭出しで鳴り直す。** シーンの長さと曲の長さが
合っていないと、クライマックスの途中で曲が頭から鳴る。

実測した例(v70時点):

| | 本文 | 自然なテンポでの所要 | 旧 crimson 4:22 | 新 crimson 4:49 |
|---|---|---|---|---|
| 第四話 | 23行 / 470字 | 44〜85秒 | 影響なし | 影響なし |
| **最終話** | **101行 / 2,619字** | **約4:51** | **climax中にループしていた** | **ほぼ継ぎ目を踏まない** |

曲を差し替えるときは、**その曲が鳴る区間の本文量を測る**。
`{bgm:"x"}` から次の `{bgm:...}` または `{ed}`/`{fin}` までの文字数を数えて、
34ms/字 + 1行あたり2秒程度で見積もると実感に近い。

ED曲は話数ごとに固定割り当てがある(`EDMAP`)。最終話だけ
`playBgm("ephemeral", false)` で**ループを切って**フルコーラス1回鳴らしている。

## 7. メモリ ── 犯人は累積ではなく固定費

実測(headless Chromium / 390x844 / renderer プロセスの RSS):

| 状態 | renderer | 増分 |
|---|---|---|
| 空の Chromium | 156 MB | — |
| **ファイルを開いてタイトル表示** | **322 MB** | **+166 MB** |
| 第一話を1本 | 521 MB | +199 MB |
| 第十話 | 712 MB | |
| **最終話(ピーク)** | **827 MB** | **+671 MB** |

**+166MB は素材を1枚も表示する前の値。** 34.8MBのHTMLドキュメント本体と、
JSヒープに文字列として常駐する32.7MBのbase64が主因。
**これが単一ファイル設計の固定費で、削るならここ。**

### 潰した推測(同じ回り道をしないために)

- **画像のデコード蓄積は主因ではない。** 58枚を展開すると理論上108MBになるが、
  背景29枚を一巡させても **+38MB** しか増えず、Chromium は積極的に捨てていた。
  108MB は到達しない上限値。「理論値が大きいから犯人」と決めつけないこと
- **音声キャッシュはシロ。** `getBuffer` が現在の曲以外の `bufCache` を削除し、
  `playBgm` は `curSrc=null` を退避より前に実行するので古いバッファはGC可能。
  ただし**デコード済み1本で最大49MB**(4:49をFloat32で展開)
- **リークではない。** 同じ話を6回連続で回しても1回あたり約10MBのじわ増えで、
  DOMノード329・保留タイマー3本と溜まっていない。
  後半で増えるのは**触る素材の種類が増えるから**

### 未確定

iOS Safari のタブ上限はデスクトップ Chromium よりはるかに厳しいが、
**翔平の実機での計測はまだ行っていない。** 「iPhoneで落ちる」と断定しないこと。
固まる報告が来たら、**どの画面か**を先に聞く。ピークは最終話。

## 8. 動画背景はスプライトより上に出る

`#bgv` は `z-index:3` で**スプライトより上**。
動画にキャラクターが写っている場合、`{spr:"none"}` を併せて入れないと
スプライトと二重に表示される。

```js
 {spr:"none"},
 {bgv:"koya"},
 ...
 {bgv:""},        // 明示的に消す
 {spr:"yukata"},
```

`{bgv:…}` は `bg` と同じく**定義されたときだけ作用する**ので、
消すまで表示が残る。

`vid` で始まる ASSETS のキーは `VMAP` に自動で入る。
`verify.cjs` は `bgv:"koya"` に対して `ASSETS.vidKoya` の実在を確認する。

## 9. `performance.memory` は当てにならない

量子化された値を返すので、実際には増えているのに**同じ数字が出続ける**。
全16話を通しても `104.0MB` のまま動かなかった。

実メモリは `ps` でレンダラプロセスの RSS を見る:

```python
def renderer_rss():
    out = subprocess.run(["ps","-o","rss=,args=","-C","chrome"],
                         capture_output=True, text=True).stdout
    return sum(int(l.split(None,1)[0]) for l in out.splitlines()
               if len(l.split(None,1))>=2 and "--type=renderer" in l.split(None,1)[1]) / 1024
```

## 10. 存在しない定数を発明しない

`BGM_VOL` という定数を使うコードを書いたが、そんなものは存在しなかった。
音量はコードベース自身の書き方で `state.bgmOn?0.9:0` と書く。

**新しいコードを書く前に、同じことをしている既存の箇所を grep して
その書き方に合わせる。** この作品はエンジンを手書きで育てているので、
一般的な命名の推測が当たらない。

同種のミス:

- `#bg` は存在しない。背景は `#bgA` / `#bgB` の2枚でクロスフェードする
- `SPMAP` はグローバルに露出していない
- 本文の表示先は `#msgText`(`#txt` ではない)
- MUSIC ROOM は `#btnMusic` から開く。タイトルの `#btnSndTest` は音の疎通確認

## 11. 読み上げの voiceId は2箇所にある

同じハッシュ計算が**本体のJSと `tools/voicelist.py` の両方**にある。
片方だけ変えると、収録台本のIDと本体が参照するIDがズレて**声が鳴らなくなる**。

| | |
|---|---|
| 本体 | `crc/index.html` の `voiceId()` と `VOICE_KEY` |
| 台本 | `tools/voicelist.py` の `voice_id()` と `VOICE_KEY` |

JS は `charCodeAt`(UTF-16コードユニット)なので、Python 側は `utf-16-le` に
エンコードして合わせている。`ord()` で書くとBMP外の文字でズレる。

**話者を増やしたら `VOICE_KEY` を両方に足す。** 片方だけだと、その話者の行が
`etc` に落ちて別のIDになる。

一致確認はこれで取れる(v71時点の実測値):

| 話者 | 本文 | voiceId |
|---|---|---|
| エルザ | 「エルザ。それ以外に、あなたが知る必要のあることは何もない」 | `el-a188f84e` |
| (地の文) | 雨の音がする。 | `narr-524025c9` |
| ユウジ | 「エルザ。それ以外に、あなたが知る必要のあることは何もない」 | `yu-17180eb5` |

**なぜ添字ではなくハッシュなのか:** この作品の増築は「間に挟む」方式なので
添字は必ずずれる。行を挿すたびに全部の収録が迷子になるのを避けるため。
本文を書き換えたときはIDが変わる ── これは意図した挙動で、
録り直しが必要な行が自動で外れる。

## 12. TTS の onend は来ないことがある

端末に日本語の声が無い、OSが発話を黙って捨てた、などで `onend` が発火しない。
来ないままだと `vsOnEnd` が呼ばれず **AUTO送りがそこで永久に止まる**。

`vsArmGuard()` が見積もり時間で必ず蹴るようにしてある。**この見張りを外さないこと。**

検証のしかた ── 発話を捨てる端末を偽装する:

```js
speechSynthesis.speak = function(u){};   // onend が来ない状況を作る
```

見張りなしなら0コマンド、ありなら45秒で6コマンド進む。
声が1つも無い環境では即 onerror に落ちて従来の送り速度に戻る
(実測: 声ON/OFFともに19コマンド/60秒)。

## 13. 読み上げで「間」を潰すと解説動画になる

v71 で `──` と `……` を `、` に置換した。**失敗だった。**

**台詞1,507行のうち752行(50%)がこの記号を含む。** 総数841個。
この作品は ── と …… で息を作っている。全部コンマに潰すと同じ速さで
平らに流れ、YouTubeの「ゆっくり解説」みたいな読み上げになる。

v72 で `speechParts()` にした。本文を「読む塊」と「沈黙」に割り、
区切りでは発話を切って**本当に黙る**。`──` が520ms、`……` が360ms。

**行頭・行末の沈黙も残すこと。** 「言いよどんでから話す」「言いかけて途切れる」は
この脚本では意味を持つ。整形で削ると台詞の性格が消える。

### 一言も喋らない行がある

`「…………」` のような、間そのものが台詞の行。記号を外すと空になる。
空のまま `speakLine` に渡すと即 onEnd が呼ばれ、**AUTOがその行を一瞬で送る** ──
間が消えるだけでなく、普通の行より速くなるので目立つ。

点の数 × 240ms(400〜1600msに収める)の沈黙を返すようにしてある。

**整形を触ったら、全話に通して parts が空になる行が0件であることを必ず再確認する:**

```js
// ブラウザのコンソールで
EP_ORDER.flatMap(ep => (EPISODES[ep]||[]).filter(c=>c&&c.t)
  .filter(c => speechParts(c.t).length===0))
```

### OSの声の抑揚は設定では変えられない

iOS なら Kyoko。rate / pitch / 間で「平らさ」は減らせるが、**感情は出ない。**
そこを埋めるのが `VOICE_CLIPS` への収録差し替えで、**TTSは代役であって完成形ではない。**
抑揚の不満を rate/pitch の調整で解こうとしても限界がある。

## 14. BGMのゲインは5箇所から書かれている

`bgmGain.gain` を書き換えている場所:

| 場所 | 何を書くか |
|---|---|
| `playBgm` | `state.bgmOn?0.9:0` |
| `stopBgm` | `setTargetAtTime(0, …)` |
| `btnBgm` のトグル | `state.bgmOn?0.9:0` |
| `ensureCtx` 周辺 | 初期値 |
| MUSIC ROOM の再生 | `setValueAtTime(state.bgmOn?0.9:0, …)` |

`ambGain.gain` も `updateAmb()` が `ambTarget()` の値で上書きする
(BGM再生中は0.05、無再生時は0.45)。

**音量を一時的に変えたいとき、この2つに直接書くと必ず喧嘩する。**
どちらかが相手の値を上書きして、下げたまま戻らない/下がらない、のどちらかになる。

v73 の読み上げダッキングは**独立した段を1つ挟んで**解決した:

```
bgmGain ─┐
         ├→ duckGain → destination
ambGain ─┘
```

`duckGain` は `voiceDuck(on)` しか触らない。既存のゲインは一切変えていない。
**同じ要領で、他の一時的な音量変更も専用段を足すこと。**

### 戻し忘れると曲が小さいまま戻らない

一時的に下げる仕組みを作るときの一番怖い壊れ方。
**終了経路を全部洗い出して、全部で戻す。** 読み上げの場合は3つあった:

1. 普通に読み終わる → `vsDone()`
2. 発話中に止められる / 別の行へ移る → `stopVoice()`
3. `onend` が来ない端末 → 見張りタイマー → `vsDone()`

3番は忘れやすい。`onend` を信じて書くと、来ない端末で曲が永久に小さいままになる。

## 15. 位置を戻すとき、頭から再生し直してはいけない

LOGから過去の行へ戻る、という機能を作るとき、素直に思いつくのは
「0 から目的の添字まで命令を流し直して世界を組み立てる」だが、**これは間違い。**

シナリオには `choice` と `jump` と `ifFlag` がある。線形に流し直すと
**実際には通らなかった分岐の背景・曲・立ち絵まで拾ってしまう。**

正しいのは**表示した時点の世界を控えておくこと**:

```js
backLog.push({n, t, i:state.i, ep:state.ep, w:worldNow()});
```

控えるのは `bg / dim / spr / bgm / bgv / amb / wash / bat` の8つ。
**`run()` の分岐側で記録する**こと ── `setBg()` などの中ではない。
`bg` 命令が `bgv` を止めるといった**命令の副作用まで1箇所で見たい**から。

### 戻れるのは同じ話の中だけ

別の話へ飛ぶとフラグと世界が噛み合わない。`e.ep===state.ep` で閉じる。
`backLog` は話をまたいで貯まるので、**ここを閉じないと「戻れそうに見えて壊れる行」ができる**
(v74 では `startGame` で `backLog` 自体をクリアした)。

### フラグは巻き戻さない

既に起きたことは起きたままにする。巻き戻すと `ifFlag` の分岐が変わって、
戻る前と違う道を通ってしまう。

## 16. `.epBtn` の一括バインドは data-ep を持たないボタンを壊す

チャプター画面のボタンはまとめて `onclick` を張られている:

```js
document.querySelectorAll(".epBtn").forEach(b=>{
  if(b.id==="btnMusic"||b.id==="btnLiner") return;   // ← 除外が要る
  b.onclick=e=>{ startGame(b.dataset.ep,false); };
});
```

`.epBtn` の見た目を使いたいだけのボタン(MUSIC ROOM、LINER NOTES)は
`data-ep` を持たない。除外し忘れると **`startGame(undefined)` が呼ばれる**。
`EPISODES[undefined]` は `EP1` にフォールバックするので、
**エラーも出ずに第一話が始まる** ── 一番気づきにくい壊れ方。

**`.epBtn` を付けたボタンを足したら、必ずこの除外リストにも足す。**

### 同じ囲いの id 重複にも注意

`chGrid` は id として4回使われていた。CSSセレクタは重複idにも全部当たるので
**見た目では気づけない**。気づいたのは、id を持たず class だけの5つ目が
`display:block` になってボタンの幅が半分になっていたから。

**グリッドの指定は id ではなく class で書くこと**(`.chGrid`)。
id の重複はこれで確認できる:

```js
const ids=[...document.querySelectorAll('[id]')].map(e=>e.id);
ids.filter((v,i)=>ids.indexOf(v)!==i);
```
