# ススデパ原価計算スキル

現場の料理人が、感覚で作っている料理の原価を数字にするための道具。
使う相手は札幌ススキノのバイキング・VIPカウンター・居酒屋営業を回している厨房。

## 基本姿勢

- **数字を勝手に作らない。** 分からない単価は「分からない」と言う。推定するときは推定と明示し、根拠（サイズ表記から1尾何gと見た、など）を書く。
- **味と調理の話も一緒にする。** 原価だけ出しても現場では使えない。「この食材はこの料理だと味が消える」「この歩留まりは卸し手で変わる」といった調理側の指摘を必ず添える。
- **削る提案は原価だけで判断しない。** 高原価でも看板になっている品は残す。原価が高くて看板にもなっていない品が最優先の見直し対象。
- 相手はプロの料理人。調理工程の基本は説明しない。単価・歩留まり・構成の話に集中する。

## 単価マスターの構造

列は固定：`分類 / 食材名称 / 仕入先 / 仕入単価 / 単位 / 入り数(gor個) / 歩留まり(%) / グラム単価(円)`

グラム単価 = `仕入単価 ÷ 入り数 ÷ 歩留まり`

### 単位の正規化ルール

| 単位表記 | 入り数 | 意味 |
|---|---|---|
| kg, ｋｇ, Kg, KG, Ｋｇ | 1000 | 円/g |
| L, Ｌ, ℓ | 1000 | 円/ml |
| 100g | 100 | 円/g |
| 個・本・枚・PC・袋・尾・丁・玉・束・箱・CS・肩・杯・缶・瓶 | 1 | 円/単位 |

- 歩留まりの既定値は 1.0（100%）。実測が出た品目だけ上書きする。**勝手に歩留まりを推定して入れない。**
- 仕入単価が空欄の行は時価品。グラム単価も空欄のまま残す。埋めない。

### 名寄せの罠

- VLOOKUPは最初の一致行しか拾わない。同名で仕入先違いがある場合、下の行は永久に使われない。
- 対処は食材名称に仕入先を足す（例：`宗八カレイ(ヤマヨ)` / `宗八カレイ(知床)`）。
- レシピ側の略称（「サーモン」「大トロ」）とマスターの正式名（「チリ産 銀鮭フィーレ トリムＣ」）は一致しない。レシピシートには照合フラグ列を置き、`未登録` を可視化する。
- **全件を直そうとしない。** レシピで実際に呼ぶ食材だけ直せば実害はない。

## 原価計算の型

1. **仕込み単位で出す。** 1皿単位ではなく「2kg仕込みで何個」。盛付数が変わっても割り戻せる。
2. **歩留まりは主材料にかける。** 使用量の合計にかけない。衣や調味料は製品に残らない。
3. 出す数字は `1仕込みの原価` / `1個あたり原価` / `100gあたり原価` / `原価率`。
4. バイキングは **一人あたり** で見る。大皿を10人が取り分けるなら1皿原価÷10。1皿原価だけ見ると寿司と比較できない。
5. 揚げ物の衣は、まぶし粉の全量ではなく実付着量（3〜7割）でも試算を並べる。

## 時価品の扱い

生鮮魚介・青果は当日にならないと単価が出ない。マスターに固定単価を持たせない。

- レシピ計算シートには「単価 手入力」列を置き、自動参照より優先させる。
- 紙の納品書が来る仕入先がある。写真から品名・数量・単価を読み取って表に起こす対応をする。読めない箇所は推測で埋めず、確認事項として列挙する。
- 丸一本仕入れ（本鮪など）は、可食部歩留まりを1本ごとに記録する運用を勧める。記録項目は「誰が捌いたか・ラウンド重量・柵の総重量」の3つ。

## 出力の使い分け

| 用途 | 形式 |
|---|---|
| 厨房に貼る・新人に渡す標準レシピ | docx（A4一枚に収める。原価表＋工程＋注意点） |
| 全商品の原価一覧・原価率比較 | xlsx |
| 社内LINE共有 | プレーンテキスト。■と数字だけ。表組みは使わない |
| 会話の中での確認 | markdown表 |

docxを作るときは `docx` スキルを、xlsxは `xlsx` スキルを先に呼ぶ（Claude Code なら Skill ツール。`/mnt/skills/public/<名前>/SKILL.md` が見える環境ならそれを読む）。

## よくある落とし穴

- **サイズ等級のL** を容量のLと誤読する。「大根 2L」「軟白ネギ 3L」は等級。容量として拾うのは `1.8L` のように小数点付きか、`ml`/`cc` 表記のときだけ。
- **ケース入数の×N** を、単位が「本」「個」の行にも掛けてしまう。単位が C/S・箱・ケースのときだけ掛ける。
- **サイズ表記の読み違い。** `有頭20-30 2kg` は「1kgあたり20〜30尾」で2kg入り。1尾40〜60尾分の単価になる。
- インフォマートのマイカタログは登録数≠使用品目数。単価0や重複登録が大量に混ざる。実使用は直近3か月の発注実績で見る。
